# Implementation decisions

- **Locked runtime:** CPython 3.12, ZenML 0.96.4, MLflow 3.16.1, pandas 2.3.3, PyArrow 23.0.1 and google-play-scraper 1.2.7. `uv.lock` records the full resolution. The local supplied reference trees informed API use; neither is installed directly.
- **Raw store:** SQLite transactions plus a seed baseline and append-only changed-row versions. A committed revision sequence selects the last version of each record at or before that sequence. Checkpoints live in the same database/transaction. Captures remain ordinary immutable files outside it. The original seed is never changed.
- **Snapshot store:** ZenML's pandas materializer writes one workable dataset output. Raw references and preparation/tracking reports are small separate artifacts. Validation does not return a second dataframe output. Caching is disabled so each run has a new snapshot.
- **Publication:** a SQLite catalog records only validated completed runs. Latest means most recently published, not latest raw revision or latest attempted ZenML run. Failed preparation/tracking/publication cannot replace it. A completed run can be published again idempotently. Earlier versions are retained.
- **MLflow:** the ZenML step selects `voc-mlflow` and logs parameters/metrics through MLflow's Python API inside the integration-managed run. Its explicit local SQLite tracking URI is separate from ZenML artifact storage. The MLflow server reads that same backend for its UI. ZenML 0.96.4 requires credentials for an HTTP MLflow tracker; this local single-container prototype instead uses the supported database URI. Authenticated remote tracking is a future configuration change. No dataset is logged to MLflow.
- **Runtime topology:** one image/container, four supervised processes, one persistent root. ZenML's local orchestrator/client and server use the same metadata store. Docker host ports bind to loopback. Jupyter retains token authentication. S3, shared multi-user deployment and cloud metadata databases are outside this iteration.
- **Date normalization:** the seed truncates `record_date` to a date even for second-precision records. Preparation takes `updated_at` for `source_updated_at`, and `published_at` for publication/edit-family provenance, retaining the source timestamp and timezone. Day precision stays date-only. The report records the number of recovered timestamps; raw values remain intact.
- **Notebook context:** the supervisor sets absolute `VOC_DATA_DIR`, `ZENML_CONFIG_PATH` and `ZENML_CUSTOM_SOURCE_ROOT` before starting Jupyter. ZenML 0.96.4 requires a source root even when loading a standard dataframe artifact from an interactive kernel. Consumers do not need notebook-specific filesystem paths.
- **Package boundary:** `voc` is built on its own. The workspace member `ml-project` installs the `voc-ml` entry point and project `src/` code; it is only included in the ML dependency group. All collector adapter code is local to this prototype, adapted from `001-collector` with no runtime imports from that project.

Reference material inspected: `Raw/code/zenml-main` MLflow experiment tracker flavor/integration, pandas materializer and pipeline/step run models; `Raw/code/mlflow-master` backend/artifact store documentation; `Raw/code/prices-predictor-system` pipeline/Click separation; `prototypes/001-collector` source parsers and bounded collection tests; `marimo/collector/unified_dataset.py` identity/date mapping.
